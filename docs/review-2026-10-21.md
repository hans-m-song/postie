# Module and test review — 2026-10-21

Review of the current working tree after documentation and formatting cleanup. Five independent reviewers examined SwiftUI, Core, automation/control/CLI, and two test-only scopes. The SwiftUI reviewer used the local `swiftui-pro` skill and its routine references. No finding is attributed to cleanup without a comparison baseline.

All 279 existing package tests, release builds and signatures passed. Source findings below are static, not runtime reproductions. Test findings concern confidence and reliability, not demonstrated production defects. No functional refactor or review-finding fix was applied in this cleanup.

## Module boundaries

```text
PostieApp: UI + single workspace/execution coordinator
    |                 |                       |
    v                 v                       v
PostieCore <--- PostieAutomation <--- PostieControl <--- PostieCLI
    |           commands/patches      HTTP/MCP + IPC     arguments/stdin
    |           output projection    authentication     JSON envelopes
    |
    +-- template/query preparation
    +-- execution + response-body leases
    +-- configuration/index/move recovery
    +-- vault + encrypted snapshot context
```

Core has no external package dependencies. AppModel is the sole workspace writer/execution owner; extracting helpers must not introduce a second writer or independent execution state. CLI and MCP deliberately have separate projections and trust channels. Most boundaries are coherent; a broad architectural rewrite is not justified by this review.

The largest concentration is AppModel, which also holds scene navigation, presentation timing and automation routing. Prioritize narrow seams: scene navigation ownership, view-local elapsed-time presentation, frozen snapshot sensitivity, and shared transport budgets. Keep mutation/execution coordination centralized.

## Source findings

### AppModel.swift — snapshot sensitivity context (priority 1, medium)

[AppModel.swift:858](../Sources/PostieApp/AppModel.swift#L858) projects saved request templates with a synthetic collection lacking the original authentication context. [requestJSON at line358](../Sources/PostieApp/AppModel.swift#L358) derives custom sensitive header names from request/collection authentication. A literal override of an inherited custom API-key header can therefore appear through `snapshots.get`, including when response viewing is Block, although live `requests.get` masks it.

Preserve the frozen submitted `sensitiveNames`/`secretNames` for snapshot request-template projection. Authentication metadata alone is insufficient when a manual override suppressed inherited auth. This is a request-template masking issue; the explicitly selected unredacted response mode is not itself a defect. High static confidence; synthetic reproduction remains the next gate.

### LocalIPC.swift and CLI main.swift — wire budgets (priority 2, medium)

[LocalIPC.swift:234](../Sources/PostieControl/LocalIPC.swift#L234) limits the entire command frame to1MiB, while [CLI main.swift:53](../Sources/PostieCLI/main.swift#L53) limits only the argument JSON. A near-limit accepted argument becomes too large after the command envelope is added.

Replies above4MiB also fail framing and are swallowed by the connection catch instead of returning a correlated error. Five supported requests with approximately900,000-character names can make `requests.list` exceed that limit. The client then reports availability failure even while Postie is running.

Define shared wire budgets, validate serialized commands before connecting, and return a bounded error envelope for oversized results. High static confidence; no live oversized payload was created.

### CollectionStore.swift — move recovery paths (priority 3, medium)

[CollectionStore.swift:1279](../Sources/PostieCore/CollectionStore.swift#L1279) reconstructs lowercase UUID collection paths during replay, while ordinary loading accepts mixed/uppercase UUID directory names at [line1886](../Sources/PostieCore/CollectionStore.swift#L1886). On a case-sensitive filesystem, a supported directory can load normally but fail a move after commit intent is written, blocking structural writes across restart.

Use the same unique UUID-directory discovery during replay, or retain validated directory basenames in the journal. Reproduce with an isolated case-sensitive fixture before changing recovery behavior. High static confidence; not reproduced on the current volume.

### PostieApp.swift — scene navigation ownership (medium)

Rule: keep scene navigation independent, or explicitly provide one window. [PostieApp.swift:35](../Sources/PostieApp/PostieApp.swift#L35) uses WindowGroup with singleton AppModel selection/history/search state. A second window therefore shares navigation and sheet presentation.

```swift
// Current
WindowGroup { ContentView().environmentObject(model) }

// If one window is intended
Window("Postie", id: "main") { ContentView().environmentObject(model) }
```

Alternatively introduce scene-local navigation while retaining one shared workspace owner. Confirm the intended window model before implementation; native multiwindow reproduction is pending.

### VariableCompletionPopover.swift — accessibility (medium)

Rule: custom AppKit drawing needs accessibility semantics. [VariableCompletionPopover.swift:93](../Sources/PostieApp/VariableCompletionPopover.swift#L93) draws suggestions in a single NSView without row elements, roles or selection announcements.

Before: manually drawn rows only. After: accessible table rows, or explicit NSAccessibilityElement children and selection notifications. VoiceOver testing is needed; the missing semantic elements are visible in source.

### AppModel.swift — global elapsed-time publication (medium)

Rule: confine changing display-only time to its presentation. [AppModel.swift:1267](../Sources/PostieApp/AppModel.swift#L1267) publishes `now` every second even when idle. Object-wide subscribers are invalidated, including unrelated editors/sidebar/search.

Before: a workspace-wide published clock. After: view-local TimelineView around active elapsed-time labels. Invalidation is source-established; CPU/memory impact is unmeasured. This is not evidence of a memory leak.

No confirmed deprecated SwiftUI API was found. Updating Task.sleep syntax is optional modernization, not a correctness finding.

No widespread coverage-only or excessive-mocking pattern was established.
