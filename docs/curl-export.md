# Copy as cURL — T120

Implemented and user-accepted 2026-10-23, including copied request contents, placement beside Send and multiline formatting. Complex upload cases have synthetic verification; individual native acceptance is not claimed for every variant.

The current request toolbar offers Copy as cURL. Export uses the same preparation path as Send, including variable resolution, path/query encoding, collection headers, request overrides and selected authentication. It includes actual secret values by the user's explicit export policy. Missing inputs or decryption failures prevent copying. It does not send a request, execute a shell or start cURL.

The generated command targets POSIX-compatible shells, uses full cURL option names and quotes arguments as literal data. Text bodies retain UTF-8 content; original file uploads use their existing local paths. Multipart uploads use resolved part values and file metadata, with cURL constructing its own boundary. File references must still exist when the copied command is run. Unsupported representations produce an error rather than a misleading command.

Formatting follow-up implemented and user-accepted 2026-10-23: one option per backslash-continued line, with bare `curl`/option names and literal shell quoting on parameter values only. Typed flag/value arguments prevent a value beginning `--` from being mistaken for an option. Fifteen focused checks passed, including literal apostrophes/newlines and continuation placement; lint, release build and strict signature pass.

Export captures the current configuration, effective variables, collection defaults and request options. If these change during preparation, the result is rejected. Navigating away cancels the clipboard operation. No generated command is persisted or logged by Postie. The system clipboard intentionally receives the resolved command, including secrets.

This exports request intent, not an identical transport implementation. The command disables implicit curlrc loading and URL globbing, restricts initial/redirect protocols to HTTP(S), and maps automatic redirects to `--location` with ten hops. Explicit custom methods can behave differently after redirects; cURL does not know Postie's custom sensitive-header classifications, so forwarding rules differ. The overall timeout maps to `--max-time`; inactivity is approximated by connection and whole-second low-speed timeouts. The app's maximum-response-byte setting is omitted. cURL's default transport headers can differ from URLSession.

Multipart boundaries and Content-Length are generated by cURL. Explicit multipart Content-Type/Length, empty multipart bodies, HEAD bodies, NUL text, and form names or MIME metadata that cannot be represented safely produce an export error. Ordinary MIME tokens and token-valued parameters are supported; cURL form attributes cannot be injected through MIME parameters. Snapshot/history cURL export and Paste cURL remain outside this slice; saved upload snapshots contain metadata rather than the original bytes.

Verification boundaries: synthetic preparation/serialization tests cover quoting, headers/auth, URL/query, body and file operands; app-level tests cover current effective inputs and no request execution. The user confirmed the copied command and revised format; no generated command is executed during automated tests.
